# Glossário

| Termo | Significado no MEDIFY |
|---|---|
| Organização/tenant | Clínica ou operação isolada de outras |
| Platform admin/root | Administração do SaaS, separada de papel clínico |
| Membership | Vínculo operacional usuário-organização |
| Clinical assignment | Vínculo que autoriza atuação clínica |
| Contato | Identidade de relacionamento/comunicação |
| Paciente | Extensão assistencial de uma identidade |
| Lead/oportunidade | Jornada comercial/operacional no funil |
| Pipeline | Funil com estágios ordenados |
| Conversa | Contêiner de mensagens de um canal |
| Claim | Ato de um atendente assumir responsabilidade |
| Snooze | Pausa temporária até instante definido |
| WAHA | Adapter self-hosted para sessão WhatsApp |
| Campaign/broadcast | Comunicação em lote com audiência/consentimento |
| Opt-in/opt-out | Autorização/recusa de comunicação por finalidade/canal |
| Prontuário | Registros assistenciais segregados |
| Encounter | Encontro/atendimento clínico |
| Draft | Registro ainda editável e não assinado |
| Adendo | Correção encadeada de registro já assinado |
| RLS | Row-Level Security do PostgreSQL |
| Service role | Credencial server-side que ignora RLS |
| Event log | Registro persistente de eventos para consumidores |
| Idempotência | Repetir operação sem repetir efeito |
| Dead-letter | Evento falho retido para investigação/replay |
| RAG | Recuperação de fontes antes de gerar resposta de IA |
| Agent run | Execução rastreável de agente/modelo/tools |
| Handoff | Transferência da automação para humano |
| AAL2 | Nível de autenticação com segundo fator |
| RPO | Perda máxima de dados aceitável |
| RTO | Tempo máximo para restaurar serviço |
| GA | Disponibilidade geral comercial |
| Gate | Condição obrigatória para avançar estágio/release |
