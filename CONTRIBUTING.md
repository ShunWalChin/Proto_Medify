# Contribuindo com a documentação

1. Crie uma branch curta a partir de `main`.
2. Atualize documento canônico e referências afetadas.
3. Regenere inventários quando código/API/schema mudou.
4. Verifique links e procure segredos.
5. Escreva commit objetivo.
6. Abra pull request descrevendo mudança, motivo, impacto e validação.

## Critérios

- não marcar planejado como entregue;
- não inserir senha, token, chave, PII ou dado clínico;
- usar links relativos;
- preservar atribuição/licença;
- explicar decisões e invariantes;
- manter exemplos executáveis sem segredo real.
